# Platform: deploying the service and the Merchant Center app

Supports steps 1 to 3. The mechanics of Connect itself (staging, publishing, deploying, redeploying, regions) are in the `commercetools-connect` skill; this file is only what is specific to the page builder.

The source of truth for every key is the repository's `connect.yaml`; the service's own README has the full configuration table.

## What gets deployed

| Application | Connect type | Why |
|---|---|---|
| Page-builder service | `service`, endpoint `/service` | Render API, catalog ingest, MC object gateway |
| Page editor | `merchant-center-custom-application` | The authors' editor |

Both are declared in one `connect.yaml`, so one connector deploys both into a project. A connector's API client is generated by Connect from `inheritAs.apiClient.scopes`:

| Scope | Why |
|---|---|
| `manage_key_value_documents` | page, catalog and settings custom objects |
| `view_products` | product search, projections, product types |
| `view_categories` | category tree |
| `view_stores` | resolving store keys |

## Service configuration

| Key | Kind | Required | Meaning |
|---|---|---|---|
| `PB_RENDER_ORIGINS` | standard | yes | Server origins of every client allowed to render |
| `PB_EDITOR_ORIGINS` | standard | yes | Merchant Center origin(s) allowed to embed and drive the editing bridge |
| `PB_MC_ISSUER` | standard | no | The project region's MC API Gateway (cloud identifier or URL); unset disables the MC gateway. The JWT audience is the origin of `CONNECT_SERVICE_URL`, the service's public URL, which Connect provides (set it by hand only for local development) |
| `PB_CACHE_TTL_SECONDS` | standard | no | Read cache, default 15, 0 disables; drafts are never cached |
| `PB_FACET_ATTRIBUTES`, `PB_FACET_LIMIT` | standard | no | Which product attributes become listing facets |
| `LOG_LEVEL` | standard | no | |
| `PB_RENDER_KEY` | secured | yes | What clients present on render calls |
| `PB_PREVIEW_TOKEN` | secured | no | Unlocks drafts and edit mode; unset disables previews |
| `PB_ADMIN_SECRET` | secured | yes | Catalog validate, push, publish from CI |

Generate the three secrets randomly and store them in the CI and platform secret stores. They are never entered in chat.

## Merchant Center app configuration

| Key | Meaning |
|---|---|
| `CUSTOM_APPLICATION_ID` | The id returned when the application is registered in Merchant Center |
| `ENTRY_POINT_URI_PATH` | The route it serves under; unique per region |
| `CLOUD_IDENTIFIER` | The project's region (`gcp-eu`, `gcp-us`, `aws-eu`, `aws-us`) |
| `INITIAL_PROJECT_KEY` | Local development project |
| `PAGE_BUILDER_SERVICE_URL` | The service URL **including** its endpoint path. Empty keeps every hook on the MC GraphQL gateway |
| `PAGE_BUILDER_SERVICE_HOOKS` | `all`, or a comma list of hook families |
| `IMAGE_PICKER_*` | Optional media picker |

The app's content-security policy lists the origins it may frame (client preview) and call. That list lives in the app's config file, so a new client origin means a change and a redeploy. Collect all origins first.

## Order of operations

1. Pick the region and the secrets; list every client origin.
2. Stage and publish the connector, deploy the **service** with the origins and secrets.
3. Read its URL (the editor needs it in step 5). Set `PB_MC_ISSUER` to the region and redeploy; the audience comes from the deployed URL Connect provides, so there is nothing to copy.
4. Register the custom application in Merchant Center with a placeholder URL; take its id.
5. Deploy the **editor** with the id, entry path, region, the service URL and `all` hooks.
6. Update the registration with the editor's deployed URL.
7. Grant view/manage to the right teams.

## Quick checks (placeholders, no secrets)

```
GET  {service-url}/status                                   -> 200 {"status":"ok"}
GET  {service-url}/v1/render?path=/&locale=..&currency=..&country=..
     X-PB-Render-Key: <key>  X-PB-Origin: <client origin>  X-PB-Wire-Version: 1
                                                            -> 404 code page_not_found on an empty project
(same call, wrong key)                                      -> 401 invalid_render_key
(same call, origin not allowlisted)                         -> 403 origin_not_allowed
```

A 404 with code `not_found` ("Route not found") is **not** the healthy empty state: it means the URL is missing the endpoint path.
